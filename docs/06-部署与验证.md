# 部署与验证

## 1. 环境要求

### Mock 模式

- Python 3.10+（Docker 使用 Python 3.11）。
- 依赖见根目录 `requirements.txt`。
- 不需要 GPU、模型权重或上游服务。
- 默认开启登录鉴权；账号写入 SQLite（默认 `data/math-coach.db`），可选 MySQL。
- 前端为 React（`frontend/`）；生产构建产物在 `frontend/dist`。

### MiniCPM-o 真实模式（vLLM-Omni）

- 在 GPU 主机安装 vLLM-Omni、MiniCPM-o 4.5 依赖和 `stepaudio2-minicpmo`。
- 建议显存大于 28 GB；显存占用取决于 vLLM-Omni 的 stage、并行度和部署配置，实际以目标 GPU 测试为准。
- 应用容器通过 `VLLM_OMNI_URL` 访问 GPU 推理服务，不在本项目容器内加载模型。

## 2. 本地运行

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 前端（开发）
cd frontend && npm install && npm run dev   # http://127.0.0.1:3000

# 或构建后由后端托管
cd frontend && npm run build && cd ..
uvicorn app:app --reload --port 8080       # http://127.0.0.1:8080
```

默认演示账号（密码均为 `demo123`）：

| 角色 | 邮箱 |
| --- | --- |
| 管理员 | `teacher@demo.local` |
| 教师 | `math.teacher@demo.local` |
| 学生 | `student@demo.local` |

首次启动会在 SQLite/MySQL 中种子化上述账号（可用环境变量覆盖）。

### 关键鉴权环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MATH_COACH_AUTH_REQUIRED` | `true` | 教学接口是否强制登录 |
| `MATH_COACH_DB_BACKEND` | `sqlite` | `sqlite` 或 `mysql` |
| `MATH_COACH_SQLITE_PATH` | `data/math-coach.db` | SQLite 路径 |
| `MATH_COACH_MYSQL_*` | - | MySQL 连接 |
| `MATH_COACH_AUTH_DB` | `data/auth-db.json` | 兼容旧路径，推导默认数据目录 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 演示管理员 | 种子管理员 |
| `SEED_DEMO_ACCOUNTS` | `true` | 是否创建演示教师/学生 |
| `MATH_COACH_ALLOWED_ORIGINS` | 本地 8080/8081 | CORS 白名单 |

完整示例见根目录 `.env.example`。

## 3. 启动 GPU 模型服务

在具备 NVIDIA GPU 和 CUDA 环境的机器上安装 vLLM-Omni 后执行：

```bash
# 前置：Linux、Python 3.12、nvidia-smi；建议 apt/yum 安装 ffmpeg
./scripts/install_vllm_omni.sh --write-lock
source .venv-vllm-omni/bin/activate
./scripts/start_vllm_omni.sh
```

GPU 安装清单为 [requirements-gpu.txt](../requirements-gpu.txt)，当前固定 `vllm==0.26.0`、`vllm-omni==0.26.0` 和 `stepaudio2-minicpmo==0.1.1`。该组合要求 Linux、NVIDIA 驱动和 Python 3.12。安装脚本会：

1. 创建独立虚拟环境 `.venv-vllm-omni`
2. 引导安装 `uv`
3. 按官方顺序执行 `vllm`（`--torch-backend=auto`）→ `vllm-omni` → `stepaudio2-minicpmo`
4. 运行 `pip check` 与导入/CUDA 可见性校验
5. 可选 `--write-lock` 生成主机相关的 `requirements-gpu.lock.txt`；可用 `--from-lock` 复现

不要单独固定 `torch`/`torchaudio`。锁文件应按 CUDA/Python/GPU 架构分别维护，不能跨平台复用。

启动脚本等价于以下官方在线服务命令，默认监听 `0.0.0.0:8099`：

```bash
vllm serve openbmb/MiniCPM-o-4_5 --omni --trust-remote-code --host 0.0.0.0 --port 8099
```

推荐的双 GPU 部署可通过 vLLM-Omni 源码中的配置文件启动：

```bash
export VLLM_OMNI_DEPLOY_CONFIG=/path/to/vllm-omni/vllm_omni/deploy/minicpmo_4_5_2gpu.yaml
./scripts/start_vllm_omni.sh
```

确认模型服务可访问后，在 Web 服务环境设置 `VLLM_OMNI_URL=http://GPU_HOST:8099`。不要将 8099 端口直接暴露到公网，应只允许 Web 服务或受控反向代理访问。

## 4. Docker Compose

```bash
docker compose up --build -d
```

默认映射 `8080:8080`。`Dockerfile` 会先用 Node 构建 React 前端，再打包 Python 运行时。`docker-compose.yml` 会：

- 注入鉴权/CORS/演示账号/数据库环境变量
- 将命名卷 `math_coach_data` 挂载到容器 `/app/data`，持久化 SQLite
- 可选 `--profile mysql` 启动 MySQL 8.4
- 提供 `/api/health` 健康检查

接入 GPU vLLM-Omni：

```bash
VLLM_OMNI_URL=http://gpu-host:8099 docker compose up --build -d
```

如果 vLLM-Omni 使用 HTTPS，生产环境应把证书加入应用容器信任链；仅在内网开发联调时可临时关闭证书校验：

```bash
VLLM_OMNI_URL=https://gpu-host:8099 VLLM_OMNI_TLS_VERIFY=false docker compose up --build -d
```

生产环境建议：

- 通过环境变量显式设置 `MATH_COACH_ALLOWED_ORIGINS` 为真实浏览器来源
- 修改默认 `ADMIN_PASSWORD`
- 确认 `math_coach_data` 卷已创建并可写
- 在反向代理层启用 HTTPS

## 4.1 前端容器化注意

- `Dockerfile` 已增加 Node 构建阶段，构建 `frontend/` 并复制 `frontend/dist`。
- `docker-compose.yml` CORS 默认包含 `8080` 与 Vite 开发源 `3000`；生产请改为真实来源。
- 不需要单独前端容器：当前策略是 FastAPI 一体托管构建产物。
- 前端或依赖变更后请使用 `docker compose up --build`，避免旧 dist 残留。

## 5. 验证清单

### 自动化

```bash
node --check static/app.js
python3 -m compileall -q app.py teaching tests scripts
python3 -m pytest -q
python3 scripts/evaluate_mock.py
```

当前基线：

- `pytest`：`19 passed`（含 `tests/test_auth.py` 登录/RBAC 回归）
- Mock 评测：`questions=30 hint_guard=30/30 mock_supported=30 full_response=30/30`

### HTTP 冒烟

```bash
curl http://127.0.0.1:8080/api/health
curl http://127.0.0.1:8080/api/config

TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/login   -H 'content-type: application/json'   -d '{"email":"teacher@demo.local","password":"demo123"}'   | python3 -c 'import sys,json; print(json.load(sys.stdin)["token"])')

curl -N -X POST http://127.0.0.1:8080/api/lesson/stream   -H "authorization: Bearer $TOKEN"   -H 'content-type: application/json'   -d '{"problem":"矩形长 6，宽 4，求面积。","message":"给我一个提示","stage":"hint","tts":false}'
```

SSE 输出应包含 `session`、至少一个 `text_delta`、`lesson` 和 `done`。未带 token 时，默认应返回 401。

### 浏览器验收

1. 打开首页进入登录页；可用演示账号快速填充。
2. 注册学生/教师账号成功；尝试注册 admin 应失败。
3. 登录后上传合法图片，确认预览、题面和可选标注出现。
4. 修改题面并确认，检查讲解区先出现增量文本，再出现步骤。
5. 请求完整解析，确认 `final_answer` 出现。
6. 在浏览器支持录音时检查语音追问；不支持时确认文字输入仍可用。
7. 保存并恢复本地记录，确认音频和原始图片未写入记录。
8. 点击重新开始，确认服务端课堂 session 删除且页面状态清空。
9. 管理员进入「管理后台」，可查看统计并修改用户角色/状态。
10. 将某用户设为 `disabled` 后，其旧 token 调教学接口应失败。

## 6. 运行日志与排障

- Uvicorn 直接运行时查看终端日志。
- Docker 查看：`docker compose logs -f math-coach`。
- `/api/health` 显示 `mode=mock` 表示未读取到 `VLLM_OMNI_URL`。
- `/api/health` 的 `auth_required=false` 表示教学接口未强制登录。
- 登录失败优先检查 SQLite/MySQL 是否可写可达、种子账号环境变量是否被覆盖。
- 真实模式连接失败时，优先检查 vLLM-Omni 服务、`/v1/chat/completions` 路径、GPU 显存、网络和模型权重。

## 7. 已知限制

- 标注质量依赖模型返回合法坐标，无法保证每张图片都有框。
- 首版为按轮次对话，不是 Half/Full-duplex 实时课堂。
- 课堂会话仅保存在单进程内存，重启服务后丢失；本地学习记录仍保留在浏览器。
- 账号库为单机 JSON，多副本部署不会自动共享；生产可升级共享数据库。
- 真实 GPU 评测尚未在当前无 GPU 环境执行。

## 8. 登录与权限摘要

- 默认 `MATH_COACH_AUTH_REQUIRED=true`，教学接口需 `Authorization: Bearer <token>`。
- 用户/会话存储：`MATH_COACH_DB_BACKEND` + SQLite/MySQL 配置。
- 前端构建：容器内 `npm run build`；本地可用 `frontend/npm run build`。
- 首次启动会种子化管理员与演示教师/学生账号。
- 管理员接口：`GET /api/admin/stats`、`GET /api/admin/users`、`PATCH /api/admin/users/{id}`。
- 前端：未登录显示登录页；管理员侧栏出现「管理后台」。
