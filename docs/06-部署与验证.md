# 部署与验证

## 1. 环境要求

### Mock 模式

- Python 3.10+（Docker 使用 Python 3.11）。
- Docker 部署使用 Docker Compose v2（`docker compose`）；MySQL 场景通过覆盖文件启用健康依赖。
- 依赖见根目录 `requirements.txt`。
- 不需要 GPU、模型权重或上游服务。
- 默认开启登录鉴权；账号写入 SQLite（默认 `data/math-coach.db`），可选 MySQL。
- 前端为 React（`frontend/`）；生产构建产物在 `frontend/dist`。

### MiniCPM-o 真实模式（vLLM-Omni）

- 在 GPU 主机安装 vLLM-Omni、MiniCPM-o 4.5 依赖和 `stepaudio2-minicpmo`。
- 建议显存大于 28 GB；显存占用取决于 vLLM-Omni 的 stage、并行度和部署配置，实际以目标 GPU 测试为准。
- 应用容器通过 `config/minicpm.json` 配置的 vLLM-Omni 服务访问 GPU 推理，不在本项目容器内加载模型；`VLLM_OMNI_URL` 仅作为测试/特殊部署覆盖项。

### 关键鉴权环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MATH_COACH_AUTH_REQUIRED` | `true` | 教学接口是否强制登录 |
| `MATH_COACH_DB_BACKEND` | `sqlite` | `sqlite` 或 `mysql` |
| `MATH_COACH_SQLITE_PATH` | `data/math-coach.db` | SQLite 路径 |
| `MATH_COACH_MYSQL_*` | - | MySQL 连接（`MATH_COACH_MYSQL_PASSWORD` **无默认**，必须自定义） |
| `MYSQL_ROOT_PASSWORD` | - | Compose MySQL profile **必须**自定义，禁止 rootpass |
| `MATH_COACH_AUTH_DB` | `data/auth-db.json` | 兼容旧路径，推导默认数据目录 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 无弱默认 | 种子管理员；密码为空则跳过创建 |
| `SEED_DEMO_ACCOUNTS` | `false` | 是否创建演示教师/学生 |
| `MATH_COACH_ALLOWED_ORIGINS` | 本地开发源 | CORS 白名单；生产只填真实 HTTPS 域名 |
| `MATH_COACH_COOKIE_SECURE` | `true` | 生产/Compose 默认 Secure；仅纯 HTTP 本地开发显式设为 `false` |
| `MATH_COACH_RATE_LIMIT_PER_MINUTE` | `120` | 全局限流（0 关闭） |
| `MATH_COACH_AUTH_RATE_LIMIT_PER_MINUTE` | `20` | 登录/注册限流 |
| `MATH_COACH_ENABLE_HSTS` | 随 secure cookie | 是否下发 HSTS |
| `MINICPM_API_KEY` / `VLLM_API_KEY` | 空 | Web 应用与 GPU 服务共享的强随机 API Key；前者用于调用上游，后者传给 vLLM `--api-key` |
| `MATH_COACH_TRUST_PROXY_HEADERS` | `false` | 仅在反向代理可信且正确追加 `X-Forwarded-For` 时开启 |
| `MATH_COACH_COMPETITION_EMAIL` | `student@competition.local` | 比赛体验学生默认邮箱 |

完整示例见根目录 `.env.example`。

## 3. 启动 GPU 模型服务

在具备 NVIDIA GPU 和 CUDA 环境的机器上安装 vLLM-Omni 后执行：

```bash
# 前置：Linux、Python 3.12、nvidia-smi；建议 apt/yum 安装 ffmpeg
./scripts/install_vllm_omni.sh --write-lock
source .venv-vllm-omni/bin/activate
./scripts/start_vllm_omni.sh
```

GPU 安装清单为 [requirements-gpu.txt](../requirements-gpu.txt)，当前固定 `vllm==0.26.0`、`vllm-omni==0.26.0` 和 `stepaudio2-minicpmo==0.1.1`。该组合要求 Linux、NVIDIA 驱动和 Python 3.12。安装脚本会：

1. 创建独立虚拟环境 `.venv-vllm-omni`
2. 引导安装 `uv`
3. 按官方顺序执行 `vllm`（`--torch-backend=auto`）→ `vllm-omni` → `stepaudio2-minicpmo`
4. 运行 `pip check` 与导入/CUDA 可见性校验
5. 可选 `--write-lock` 生成主机相关的 `requirements-gpu.lock.txt`；可用 `--from-lock` 复现

不要单独固定 `torch`/`torchaudio`。锁文件应按 CUDA/Python/GPU 架构分别维护，不能跨平台复用。

启动脚本等价于以下官方在线服务命令，默认监听 `0.0.0.0:8099`：

```bash
vllm serve openbmb/MiniCPM-o-4_5 --omni --trust-remote-code --host 0.0.0.0 --port 8099
```

推荐的双 GPU 部署可通过 vLLM-Omni 源码中的配置文件启动：

```bash
export VLLM_OMNI_DEPLOY_CONFIG=/path/to/vllm-omni/vllm_omni/deploy/minicpmo_4_5_2gpu.yaml
./scripts/start_vllm_omni.sh
```

模型服务默认配置在 `config/minicpm.json`。更换服务时只需修改其中的 `base_url` 和 `model`，然后重启应用容器；Docker Compose 已将该文件挂载进容器。不要将 8099 端口直接暴露到公网，应只允许 Web 服务或受控反向代理访问。
远端启用鉴权前，先生成强随机值，并在 Web 应用与 GPU 主机使用同一个值：推荐在 `config/minicpm.json` 保留 `api_key_env: "MINICPM_API_KEY"` 并将值写入被 Git 忽略的 `.env`；私有环境也可直接填 `api_key`，但不要提交。GPU 服务读取 `VLLM_API_KEY`。`scripts/start_vllm_omni.sh` 绑定非回环地址时必须提供 `VLLM_API_KEY`，并自动追加 vLLM `--api-key`。不要把真实 API Key 提交到公开仓库。

```bash
# 在 Web 与 GPU 主机分别写入同一个随机值；此处不回显真实 Key
python3 - <<'PY'
import secrets
value = secrets.token_urlsafe(32)
print('MINICPM_API_KEY=' + value)
print('VLLM_API_KEY=' + value)
PY
```

> 注意：当前远程地址在服务端重启并加载 `--api-key` 前仍可能接受匿名请求。上线验收必须确认匿名请求返回 401，带正确 Bearer Key 返回 200。

在 GPU 主机上重启公开服务时使用：

```bash
set -a; source .env; set +a
VLLM_OMNI_MODEL=/tmp/pretrainmodel/MiniCPM-o-4_5 \
VLLM_OMNI_HOST=0.0.0.0 \
./scripts/start_vllm_omni.sh
```

重启后用无 Authorization 的 `/v1/chat/completions` 请求应返回 `401`；携带 `Authorization: Bearer $MINICPM_API_KEY` 才应返回 `200`。

## 4. Docker Compose

```bash
# 默认 SQLite，不依赖未激活的 MySQL profile
docker compose up --build -d

# MySQL；覆盖文件为 math-coach 增加 service_healthy 依赖
docker compose -f docker-compose.yml -f docker-compose.mysql.yml --profile mysql up --build -d
```

默认映射 `${MATH_COACH_PORT:-8089}:8089`。`Dockerfile` 会先用 Node 执行 `npm ci` 构建 React 前端，再打包 Python 运行时。`docker-compose.yml` 会：

- 注入鉴权/CORS/演示账号/数据库环境变量
- 以只读方式挂载 `config/minicpm.json`
- 将命名卷 `math_coach_data` 挂载到容器 `/app/data`，持久化 SQLite
- 可选 `--profile mysql` 启动 MySQL 8.4
- 默认开启 `MATH_COACH_COOKIE_SECURE=true`、`MATH_COACH_ENABLE_HSTS=true`
- 默认关闭 `MATH_COACH_TRUST_PROXY_HEADERS`；仅在可信反向代理后开启
- 提供 `/api/health` 健康检查

接入 GPU vLLM-Omni：

```bash
# 默认读取 config/minicpm.json；如需临时覆盖：
VLLM_OMNI_URL=http://gpu-host:8099 docker compose up --build -d
```

如果 vLLM-Omni 使用 HTTPS，生产环境应把证书加入应用容器信任链；仅在内网开发联调时可临时关闭证书校验：

```bash
VLLM_OMNI_URL=https://gpu-host:8099 VLLM_OMNI_TLS_VERIFY=false docker compose up --build -d
```

生产环境建议：

- 通过环境变量显式设置 `MATH_COACH_ALLOWED_ORIGINS` 为真实浏览器来源
- 修改默认 `ADMIN_PASSWORD`
- 确认 `math_coach_data` 卷已创建并可写
- 在反向代理层启用 HTTPS

比赛体验账号可在数据库所在环境执行：

```bash
python3 scripts/reset_competition_demo.py --secret-file /tmp/math-coach-competition.env
```

该脚本重置学生账号密码、登录会话、错题本和重练记录；教学会话在应用进程内存中，如需彻底清空，同时重启 Web 容器或让用户点击「重新开始」。密码文件必须能设置为仅所有者可读写；WSL/Windows 挂载盘忽略 `chmod` 时脚本会删除文件并失败。

curl http://127.0.0.1:8089/api/health

### 浏览器验收

1. 打开首页进入登录页；可用演示账号快速填充。
2. 注册学生/教师账号成功；尝试注册 admin 应失败。
3. 登录后上传合法图片，确认预览、题面和可选标注出现。
4. 点击「开启摄像头」，授权后拍摄同一道题；确认媒体流可关闭且识题结果进入同一确认流程。
5. 修改题面并确认，检查讲解区先出现增量文本，再出现步骤；提示阶段不得出现最终答案或锁定步骤结论；真实模式下确认讲解仍携带识题会话中的题图。
   - 若整页包含多道题，先确认候选题单选列表完整展示；切换题目后，题面、题图标注和后续讲解应跟随当前选择。
6. 确认“总结方法”初始禁用；发送一次文字想法或语音回答后按钮可用，点击进入 `stage=explain`，确认 `final_answer` 和方法总结出现。
7. 拍摄一张不是题目的图片，确认页面不报错，显示“未识别到题目”及重拍/手输提示，且响应 `no_problems=true`。
8. 在浏览器支持录音时检查语音追问和 TTS 打断；不支持时确认文字输入仍可用。
9. 保存并恢复本地记录，确认列表展示讲解摘要和最终答案，且音频和原始图片未写入记录。
10. 点击重新开始，确认服务端课堂 session 删除且页面状态清空。
11. 管理员进入「管理后台」，可查看统计并修改用户角色/状态。
12. 将某用户设为 `disabled` 后，其旧会话 Cookie 调教学接口应失败。
13. 使用另一个登录用户传入别人的 `session_id`，应得到新的隔离会话或删除失败。
14. 尝试上传伪装后缀/损坏/超过限制的图片，确认返回 415/413，而不是进入真实模型。

## 6. 运行日志与排障

- Uvicorn 直接运行时查看终端日志。
- Docker 查看：`docker compose logs -f math-coach`。
- `/api/health` 显示 `mode=mock` 表示模型配置的 `base_url` 为空。
- 真实识题异常且提供文本回退时前端显示显式降级提示；确认题面后讲解会携带缓存题图自动重试真实模型。没有文本回退时返回 502，应先检查模型服务可用性。
- `/api/health` 的 `auth_required=false` 表示教学接口未强制登录。
- 登录失败优先检查 SQLite/MySQL 是否可写可达、种子账号环境变量是否被覆盖。
- 真实模式连接失败时，优先检查 vLLM-Omni 服务、`/v1/chat/completions` 路径、GPU 显存、网络和模型权重。

## 7. 已知限制

- 标注质量依赖模型返回合法坐标，无法保证每张图片都有框。
- 首版为按轮次对话，不是 Half/Full-duplex 实时课堂。
- 课堂会话和题图仅保存在单进程内存，重启服务后丢失；本地学习记录仍保留在浏览器。
- 教学会话默认最多 200 个、30 分钟未活动过期。带图会话存在内存峰值，生产多实例需共享会话或采用粘性路由。
- SQLite 默认适合单实例；多副本部署应切换共享 MySQL。
- 摄像头和麦克风需要 HTTPS 或 `localhost` 安全上下文；WSL/Windows 挂载盘可能忽略 POSIX 权限。
- 响应头 `Permissions-Policy` 必须包含 `camera=(self)` 和 `microphone=(self)`；`camera=()` 会导致浏览器拦截摄像头并提示权限错误。

## 8. 登录与权限摘要

- 默认 `MATH_COACH_AUTH_REQUIRED=true`；浏览器使用 HttpOnly Cookie，脚本/测试兼容 Bearer。
- 用户/会话存储：`MATH_COACH_DB_BACKEND` + SQLite/MySQL 配置。
- 前端构建：容器内 `npm run build`；本地可用 `frontend/npm run build`。
- 首次启动会种子化管理员与演示教师/学生账号。
- 管理员接口：`GET /api/admin/stats`、`GET /api/admin/users`、`PATCH /api/admin/users/{id}`。
- 前端：未登录显示登录页；管理员侧栏出现「管理后台」。


## 9. 安全加固与 HTTPS

### 9.1 上线前检查清单

1. 设置强 `ADMIN_PASSWORD`；关闭不需要的 `SEED_DEMO_ACCOUNTS`。
2. MySQL 场景：自定义 `MYSQL_ROOT_PASSWORD` 与 `MATH_COACH_MYSQL_PASSWORD`，禁止沿用文档中的示例弱口令。
3. `MATH_COACH_ALLOWED_ORIGINS` 仅包含生产前端源（例如 `https://math.example.com`）。
4. 反向代理终止 TLS，并设置 `MATH_COACH_COOKIE_SECURE=true`、`MATH_COACH_ENABLE_HSTS=true`。
5. 确认响应头包含 `Content-Security-Policy`、`X-Content-Type-Options`、`X-Frame-Options`。
6. GPU 服务启用 API Key，重启后确认匿名请求 401、带 Key 请求 200。
7. 若依赖反向代理提供真实客户端 IP，设置 `MATH_COACH_TRUST_PROXY_HEADERS=true`，并确认代理会追加而非透传伪造的 `X-Forwarded-For` 前缀。
8. 确认 `/docs`、`/redoc`、`/openapi.json` 默认不可访问；仅在需要时临时开启。

### 9.2 Nginx 反向代理（强制 HTTPS）

```nginx
# /etc/nginx/conf.d/math-coach.conf
upstream math_coach {
    server 127.0.0.1:8089;
}

server {
    listen 80;
    server_name math.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name math.example.com;

    ssl_certificate     /etc/letsencrypt/live/math.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/math.example.com/privkey.pem;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    location / {
        proxy_pass http://math_coach;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        # SSE
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

对应应用环境变量示例：

```bash
MATH_COACH_ALLOWED_ORIGINS=https://math.example.com
MATH_COACH_COOKIE_SECURE=true
MATH_COACH_ENABLE_HSTS=true
MATH_COACH_TRUST_PROXY_HEADERS=true
```

### 9.4 会话与限流

- 浏览器登录后写入 HttpOnly Cookie：`math_coach_token`（`SameSite=Lax`，HTTPS 下 `Secure`）。
- API 仍兼容 `Authorization: Bearer`，便于脚本与测试。
- 登录/注册默认每 IP 每分钟 20 次；通用 API 120 次（可用环境变量调整或置 0 关闭）。
- 服务端仅保存登录 token 的 SHA-256 哈希；管理员修改目标用户角色/状态/密码后撤销其会话。
- 限流内存桶有上限并周期清理，避免公网伪造来源导致无界内存增长。
