## 2. 鉴权与 RBAC 设计

### 2.1 模块职责

- `teaching/rbac.py`
  - 角色常量：`student` / `teacher` / `admin`
  - `normalize_role()`：兼容历史 `user` -> `student`
  - `validate_register_payload()`：邮箱、密码强度、昵称、公开角色限制
  - `public_user()`：对外剥离密码哈希
- `teaching/auth_store.py`
  - scrypt 密码哈希与校验
  - 用户 CRUD / 登录会话 create-get-delete；服务端只保存会话 token 的 SHA-256 哈希
  - 种子管理员与演示账号
  - 管理端用户列表、角色/状态更新
- `teaching/deps.py`
  - 优先从 `Authorization: Bearer <token>` 解析当前用户，回退到 HttpOnly Cookie
  - `require_user` / `require_admin`

### 2.2 会话模型

登录会话与教学会话分离：

| 概念 | 存储 | 标识 | 生命周期 |
| --- | --- | --- | --- |
| 登录会话 | SQLite/MySQL `sessions` 表 | 随机 URL-safe token；数据库仅存 SHA-256 哈希 | 默认 7 天，可 logout |
| 教学会话 | 进程内存 `TeachingOrchestrator` | `session_id`，并绑定 `owner_id` | 进程内短期；重新开始删除，仅所有者可复用/删除 |

### 2.3 保护策略

- 公开：`/api/health`、`/api/config`、`/api/auth/login`、`/api/auth/register`
- 登录后：教学接口、`/api/auth/me`、`/api/me/profile`、`/api/auth/logout`
- 管理员：`/api/admin/*`
- `MATH_COACH_AUTH_REQUIRED=false` 时，教学接口允许匿名 fallback 用户，便于本地脚本与旧测试
- 登录/注册成功仅返回 `user` 与 `cookie_auth`；token 只写入 HttpOnly Cookie，不出现在 JSON 响应体。
- 管理员修改角色、状态或密码等敏感字段后，目标用户既有登录会话会被撤销。

### 2.4 注册规则

1. 密码 8-128 位，需同时包含字母和数字（注册时校验；种子演示账号可使用更短兼容密码）。
2. 昵称 2-32 字。
3. 角色仅 `student` / `teacher`。
4. `admin` 禁止公开注册。
5. 学生可附带 `grade`（`grade7`…`grade12`）。

## 3. 题面识别设计

### 3.1 Mock 分支

模型 `base_url` 为空或未上传图片时，`mock_recognize(problem_text, subject)` 返回输入题面；带图且没有输入文本时返回 `no_problems=true` 与重拍/手输提示，不再虚构默认例题。`subject` 由统一学科目录归一化，默认 `math`，并贯穿识题、短期会话、普通/流式讲解和练习推荐。数学 Mock 保留确定性解析，其他学科使用学科化通用步骤。

### 3.2 MiniCPM-o 分支

服务向上游发送图片和提示：要求只返回 JSON，包含 `problem` 和归一化 `annotations`，且不得解题。解析器支持裸 JSON、带 ```json 围栏的 JSON 以及夹杂前后说明文字的 JSON。

前端除文件上传外，可在浏览器通过 `getUserMedia` 打开摄像头，用 Canvas 捕获 JPEG 后复用同一条识别链路。摄像头帧只存在于浏览器内存与当前 HTTP 请求中，不落盘。

上传前置校验：

1. 声明 MIME 仅允许 `image/png`、`image/jpeg`、`image/webp`、`application/pdf`。
2. 文件大小不超过 8 MB，空文件返回 400，超限返回 413。
3. 图片文件签名必须与声明 MIME 一致，并交给 Pillow 打开、检查实际格式和 `verify()`；PDF 必须以 `%PDF-` 开头、1-20 页、页面宽高不超过 10000。
4. 图片宽高均须为 1-10000 像素，且总像素不超过 20,000,000；PDF 首页由 pypdfium2 渲染为不超过 20,000,000 像素的 PNG 后进入同一模型链路；不合法内容返回 415。
5. 真实模型识别异常时记录服务端日志；没有 `problem_text` 可回退时返回明确 502，不虚构示例题，提供 `problem_text` 时返回 `degraded=true` 与 `degraded_reason`；上传校验异常不会被 Mock 绕过。
6. 识别成功或真实识题带文本降级后，都会创建 `stage=confirm` 的短期服务端会话并缓存题图，保证学生修正 OCR 文本后仍可利用图形信息；识别成功但没有完整题目时返回 `no_problems=true`，不创建题图会话。

### 3.3 标注校验

每个标注字段约束如下：`x/y` 为 `[0,1]`，`width/height` 为 `(0,1]`，并且 `x + width <= 1`、`y + height <= 1`。最多保留 12 个合法标注。非法项单独丢弃，不使整次识题失败。

## 4. 会话编排设计

`TeachingOrchestrator` 管理 `dict[str, TeachingSession]`：

1. `create_recognition_session(...)`：识题成功或真实识题降级后创建 `stage=confirm` 的会话，并在内存中缓存题图字节与 MIME，供学生编辑题面后的首次讲解使用。
2. `get_or_create(session_id, problem, owner_id)`：session 不存在或所有者不匹配时创建新会话；普通题面变化时也创建新会话。仅当 confirm 阶段会话携带题图时，允许更新为学生修正后的题面并保留题图。
3. `commit(...)`：追加 user/assistant 两条消息，仅保留最近 16 条消息。
4. `_trim()`：超过 200 个会话时删除最早访问的会话；访问前清理超过 30 分钟未活动的会话。
5. `delete(session_id, owner_id)`：仅所有者能删除；重新开始或客户端主动清理时调用，同时释放内存中的题图。

会话更新规则：

- 识题会话允许把 `problem` 从 OCR 结果更新为学生确认后的文本。
- 一旦 `commit()` 将阶段推进，后续题面变化会创建新会话，不把旧题图带进新题。
- 会话不存在、过期、所有者不匹配或普通题面变化时，服务端总是生成新的随机 ID，不回显客户端传入的旧 ID。
- 前端在确认前移除图片会调用会话删除并清空本地 `session_id`；确认后仅隐藏预览，保留讲解所需题图上下文。

浏览器提交的 `history` 字段不会覆盖服务端历史，服务端只信任自身会话状态。

## 5. MiniCPM-o 适配器

`MiniCPMClient._payload()` 统一构造上游请求：

```json
{
  "model": "/tmp/pretrainmodel/MiniCPM-o-4_5",
  "messages": [{"role":"system","content":"..."}, {"role":"user","content":"..."}],
  "stream": true,
  "temperature": 0.2,
  "top_p": 0.8,
  "max_tokens": 512,
  "modalities": ["text", "audio"],
  "chat_template_kwargs": {"enable_thinking": false, "use_tts_template": true}
}
```

存在音频或题图时，user content 改为 OpenAI 多模态数组：文本、`audio_url`（单声道 WAV Data URL）和 `image_url`（Data URL）。题图来自当前教学会话，不要求前端重复上传。不要求 TTS 时 `modalities` 为 `["text"]` 且不传 TTS 模板参数。配置 API Key 后，上游请求携带 `Authorization: Bearer <api_key>`；未配置时保持匿名请求，生产服务端必须关闭匿名访问。

`stream()` 连接 vLLM-Omni `/v1/chat/completions`，发送 OpenAI-compatible JSON，并解析 SSE data 帧，再将事件归一化为：

- `text_delta`：模型文本增量。
- `audio_delta`：优先解析 `choices[].delta.audio.data`；当上游以顶层 `modality=audio` 表示音频时，读取 `choices[].delta.content`，服务端解码后合并。

`chat()` 复用同一事件流并聚合为普通 `LessonResponse`，保证 `/api/lesson` 仍可用于非流式调用。

## 6. SSE 详细协议

每个事件占一个 `data: JSON` 帧，帧之间以空行分隔。

```text
data: {"type":"session","session_id":"..."}

data: {"type":"text_delta","text_delta":"先观察..."}

data: {"type":"lesson","lesson":{...LessonResponse}}

data: {"type":"done"}
```

前端收到 `text_delta` 立即更新回复区；收到 `lesson` 后用结构化步骤替换临时内容。

## 7. 教学响应设计

`structured_steps()` 从 Markdown 文本中识别形如 `1. ...`、`步骤 1：...` 的行，最多生成 6 个 `Step`。`答案：` 或 `最终答案：` 后的首行被提取为 `final_answer`。提示阶段即使模型文本含答案，接口也只在 `stage=explain` 时填充 `final_answer`；生产环境仍应通过系统 Prompt 和评测监控答案泄露。

Mock 教师按方程、因式分解、一次函数、平面几何和解析几何匹配固定模板。提示阶段返回问题式引导，锁定步骤正文替换为「完整解析后再查看这一步」；完整解析阶段返回步骤、答案和方法总结。前端对锁定步骤同样做兜底隐藏，避免在最终答案字段为空时展示结论。

识题接口仍使用上游 JSON 契约获取题面与标注，但页面不会展示原始 JSON。解析层会提取完整或截断响应中的多个 `problem` 字段；若模型把整页多题合并成一个字符串，则按递增题号切分为多个候选题，并保留同一题的 (1)(2)(3) 小问。解析层会移除“识别如下”和练习栏目噪声，并将常用 LaTeX 及 `sqrt()` 转换为 ×、÷、√()、`(a)/(b)` 和 Unicode 上标。所有视觉输入先按最长边 1280 / JPEG 90 压缩，再整页按提示词逐题识别；高页整页只识别出一题时自动追加带重叠的上/下分块请求，合并去重并还原图注坐标。多页 PDF 逐页发送单图请求，成功页的题目合并后全局重编号，避免一次多图长推理触发网关超时。前端展示候选题列表；学生勾选一题后写入可编辑题面，确认时服务端只把该题文本与识别出题目的页面上下文绑定。

## 8. 音频处理

- 浏览器 `MediaRecorder` 录音后使用 `AudioContext` 重采样到 16 kHz。
- 发送格式为 Float32 PCM 的 Base64，带 `audio_sample_rate=16000`；单次录制和请求均限制 60 秒，Base64 字段最长 4,000,000 字符。
- 服务端使用严格 Base64 解码，校验字节长度按 Float32 对齐，按采样率限制最大样本数，再转换、裁剪并封装为 16-bit PCM WAV。
- 上游 TTS 返回 24 kHz 单声道 WAV，服务端合并重复 WAV 头并修正长度字段。
- 浏览器通过 WAV Data URL 播放；浏览器自动播放策略阻止时显示可重试状态，不丢失文本讲解。
- TTS 播放状态由单一 `HTMLAudioElement` 管理；点击打断、开始新录音或开始新讲解会先暂停旧音频并清理引用。

## 9. 前端状态机

| 状态 | 入口 | 允许操作 | 退出 |
| --- | --- | --- | --- |
| `auth` | 未登录 / Cookie 失效 | 登录、注册、填充演示账号 | 登录成功进入 `workspace` |
| `workspace` | 登录成功 | 上传、摄像头拍题、编辑题面、讲解、保存 | 退出登录 / 进入 admin |
| `confirm` | 初始/重新开始 | 上传、摄像头拍题、编辑题面、移除图片和识题上下文 | 点击确认进入 `hint` |
| `hint` | 确认题面或普通追问 | 获取提示、文字/语音尝试当前小步 | 完成一次可见尝试后点击“总结方法”进入 `explain` |
| `explain` | 完成一次尝试后请求完整解析 | 继续追问、用一句话总结、保存记录 | 重新开始 |
| `admin` | 管理员侧栏 | 查看统计、改用户角色/状态 | 返回课堂 |

前端：

- `localStorage.mathCoachSaved` / `mathCoachProgress` 保存学习记录与进度；学习记录仅包含题面、讲解文本、最终答案和时间，不包含原始图片或录音
- 登录 token 保存在 HttpOnly Cookie，JavaScript 不可读取；请求使用 `credentials: 'include'`；收到 401 时清理过渡期 Bearer 缓存并回到登录页
- 摄像头状态独立于文件上传状态；组件卸载、切换题目、重新开始和拍摄完成都会停止媒体流并释放轨道。
- “总结方法”按钮在学生发送一次文字想法或语音回答前禁用，并提示先完成尝试；该状态随切题、重新开始和恢复本地记录一起重置。
- 识题返回 `degraded=true` 时显示黄色警告条；`session_id` 仍保留，确认题面后讲解请求自动携带题图重试真实模型；识别成功但 `no_problems=true` 时保留拍摄预览并提示重拍或手动输入，不创建题图会话。
- `MiniCPM-o Real Mode` / `Mock Demo Mode` 标识来自公开配置和实际 lesson source，避免离线演示被误认为真实推理。

## 10. 错误与安全处理

- 非 PNG/JPEG/WebP/PDF、签名不符、超限、页数/页面非法或无法通过 Pillow/PDF 渲染校验的文件返回 400/413/415，不进入真实模型请求。
- Pydantic 对题面、消息、音频 Base64 长度和采样率做边界校验。
- 模型异常不返回 Python 堆栈；真实错误仅记录在服务端日志上下文中。
- CORS 默认只开放本地开发来源，生产部署应通过环境变量显式设置。
- CORS 白名单禁止 `*`，每项必须是仅含 origin 的 http/https URL。
- 密码哈希不可回读；`public_user` 不返回 `password_hash`；登录响应不返回会话 token。
- `/api/session/{session_id}` 仅删除当前用户拥有的服务端课堂会话，不影响登录会话和本地记录。
- OpenAPI/Swagger 默认关闭；CSP `script-src 'self'`，前端脚本由本地构建产物提供。
- `Permissions-Policy` 为 `camera=(self), microphone=(self)`；摄像头与麦克风仅对同源课堂页面开放，公网访问仍必须使用 HTTPS 或 localhost 安全上下文。
- 限流默认登录/注册每 IP 每分钟 20 次、通用 API 120 次；仅当 `MATH_COACH_TRUST_PROXY_HEADERS=true` 时信任代理追加的 `X-Forwarded-For` 最后一跳。


## 11. 前端实现（React）

- 目录：`frontend/`（Vite + React 19 + TypeScript）
- 入口：`frontend/index.tsx` / `frontend/App.tsx`
- 服务层：`frontend/services/{api,authService,adminService,lessonService}.ts`
- 登录门禁：无有效 Cookie 时渲染 `AuthModal`；401 清理会话并回到登录
- 视图：`workspace` / `history` / `notebook` / `admin`
- SSE：`POST /api/lesson/stream` 解析 `session` / `text_delta` / `lesson` / `done`
- 拍题：`getUserMedia` 视频流 + Canvas JPEG 捕获，复用 `POST /api/recognize`
- 语音：`MediaRecorder` 录音 + 16 kHz Float32 PCM 编码 + 单实例 TTS 播放与打断
- 构建：`npm run build` → `frontend/dist`，由 `app.py` 托管；无 dist 时回退 `static/`
