# 详细设计

## 1. 运行时配置

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `VLLM_OMNI_URL` | 空 | 真实模型 OpenAI-compatible 服务地址；为空则 Mock |
| `MINICPM_GATEWAY_URL` | 空 | 兼容旧配置；仅当 `VLLM_OMNI_URL` 为空时生效 |
| `MINICPM_MODEL` | `openbmb/MiniCPM-o-4_5` | `/api/config` 展示的模型名 |
| `MATH_COACH_ALLOWED_ORIGINS` | 本地 8080/8081 来源 | 逗号分隔的 CORS 白名单 |
| `VLLM_OMNI_TLS_VERIFY` | `true` | HTTPS vLLM API 是否校验证书 |
| `MATH_COACH_AUTH_REQUIRED` | `true` | 教学 API 是否强制登录 |
| `MATH_COACH_DB_BACKEND` | `sqlite` | 账号库后端：`sqlite` 或 `mysql` |
| `MATH_COACH_SQLITE_PATH` | `data/math-coach.db` | SQLite 文件路径 |
| `MATH_COACH_MYSQL_*` / `MATH_COACH_MYSQL_DSN` | - | MySQL 连接配置 |
| `MATH_COACH_AUTH_DB` | `data/auth-db.json` | 兼容旧路径；用于推导默认 SQLite 目录 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` / `ADMIN_NICKNAME` | 演示管理员 | 种子管理员账号 |
| `SEED_DEMO_ACCOUNTS` | `true` | 是否种子化演示教师/学生 |
| `DEMO_TEACHER_*` / `DEMO_STUDENT_*` | 演示教师/学生 | 演示账号邮箱、密码、昵称、年级 |

## 2. 鉴权与 RBAC 设计

### 2.1 模块职责

- `teaching/rbac.py`
  - 角色常量：`student` / `teacher` / `admin`
  - `normalize_role()`：兼容历史 `user` -> `student`
  - `validate_register_payload()`：邮箱、密码强度、昵称、公开角色限制
  - `public_user()`：对外剥离密码哈希
- `teaching/auth_store.py`
  - scrypt 密码哈希与校验
  - 用户 CRUD / 登录会话 create-get-delete
  - 种子管理员与演示账号
  - 管理端用户列表、角色/状态更新
- `teaching/deps.py`
  - 从 `Authorization: Bearer <token>` 解析当前用户
  - `require_user` / `require_admin`

### 2.2 会话模型

登录会话与教学会话分离：

| 概念 | 存储 | 标识 | 生命周期 |
| --- | --- | --- | --- |
| 登录会话 | SQLite/MySQL `sessions` 表 | Bearer token | 默认 7 天，可 logout |
| 教学会话 | 进程内存 `TeachingOrchestrator` | `session_id` | 进程内短期；重新开始删除 |

### 2.3 保护策略

- 公开：`/api/health`、`/api/config`、`/api/auth/login`、`/api/auth/register`
- 登录后：教学接口、`/api/auth/me`、`/api/me/profile`、`/api/auth/logout`
- 管理员：`/api/admin/*`
- `MATH_COACH_AUTH_REQUIRED=false` 时，教学接口允许匿名 fallback 用户，便于本地脚本与旧测试

### 2.4 注册规则

1. 密码 8-128 位，需同时包含字母和数字（注册时校验；种子演示账号可使用更短兼容密码）。
2. 昵称 2-32 字。
3. 角色仅 `student` / `teacher`。
4. `admin` 禁止公开注册。
5. 学生可附带 `grade`（`grade7`…`grade12`）。

## 3. 题面识别设计

### 3.1 Mock 分支

未配置 vLLM-Omni 或未上传合法图片时，`mock_recognize(problem_text)` 返回输入题面；没有输入时使用示例题 `2x + 5 = 17`。

### 3.2 MiniCPM-o 分支

服务向上游发送图片和提示：要求只返回 JSON，包含 `problem` 和归一化 `annotations`。解析器支持裸 JSON、带 ```json 围栏的 JSON 以及夹杂前后说明文字的 JSON。

### 3.3 标注校验

每个标注字段约束如下：`x/y` 为 `[0,1]`，`width/height` 为 `(0,1]`，并且 `x + width <= 1`、`y + height <= 1`。最多保留 12 个合法标注。非法项单独丢弃，不使整次识题失败。

## 4. 会话编排设计

`TeachingOrchestrator` 管理 `dict[str, TeachingSession]`：

1. `get_or_create(session_id, problem)`：session 不存在或题面变化时创建新会话。
2. `commit(...)`：追加 user/assistant 两条消息，仅保留最近 16 条消息。
3. `_trim()`：超过 200 个会话时删除最早访问的会话。
4. `delete(session_id)`：返回是否删除成功；重新开始或客户端主动清理时调用。

浏览器提交的 `history` 字段不会覆盖服务端历史，服务端只信任自身会话状态。

## 5. MiniCPM-o 适配器

`MiniCPMClient._payload()` 统一构造上游请求：

```json
{
  "model": "openbmb/MiniCPM-o-4_5",
  "messages": [{"role":"system","content":"..."}, {"role":"user","content":"..."}],
  "stream": true,
  "temperature": 0.2,
  "top_p": 0.8,
  "max_tokens": 512,
  "modalities": ["text", "audio"],
  "chat_template_kwargs": {"use_tts_template": true}
}
```

存在音频或图片时，user content 改为 OpenAI 多模态数组：文本、`audio_url`（16 kHz 单声道 WAV Data URL）和 `image_url`（Data URL）。不要求 TTS 时 `modalities` 为 `["text"]` 且不传 TTS 模板参数。

`stream()` 连接 vLLM-Omni `/v1/chat/completions`，发送 OpenAI-compatible JSON，并解析 SSE data 帧，再将事件归一化为：

- `text_delta`：模型文本增量。
- `audio_delta`：`choices[].delta.audio.data` 中的 Base64 WAV chunk，服务端解码后合并。

`chat()` 复用同一事件流并聚合为普通 `LessonResponse`，保证 `/api/lesson` 仍可用于非流式调用。

## 6. SSE 详细协议

每个事件占一个 `data: JSON` 帧，帧之间以空行分隔。

```text
data: {"type":"session","session_id":"..."}

data: {"type":"text_delta","text_delta":"先观察..."}

data: {"type":"lesson","lesson":{...LessonResponse}}

data: {"type":"done"}
```

前端收到 `text_delta` 立即更新回复区；收到 `lesson` 后用结构化步骤替换临时内容。

## 7. 教学响应设计

`structured_steps()` 从 Markdown 文本中识别形如 `1. ...`、`步骤 1：...` 的行，最多生成 6 个 `Step`。`答案：` 或 `最终答案：` 后的首行被提取为 `final_answer`。提示阶段即使模型文本含答案，接口也只在 `stage=explain` 时填充 `final_answer`；生产环境仍应通过系统 Prompt 和评测监控答案泄露。

Mock 教师按方程、因式分解、一次函数、平面几何和解析几何匹配固定模板。提示阶段返回问题式引导，完整解析阶段返回步骤和答案。

## 8. 音频处理

- 浏览器 `MediaRecorder` 录音后使用 `AudioContext` 重采样到 16 kHz。
- 发送格式为 Float32 PCM 的 Base64，带 `audio_sample_rate=16000`。
- 上游 TTS 返回 24 kHz 单声道 WAV，服务端合并重复 WAV 头并修正长度字段。
- 浏览器直接以 WAV Blob 播放；浏览器自动播放策略阻止时静默忽略播放异常。

## 9. 前端状态机

| 状态 | 入口 | 允许操作 | 退出 |
| --- | --- | --- | --- |
| `auth` | 未登录 / token 失效 | 登录、注册、填充演示账号 | 登录成功进入 `workspace` |
| `workspace` | 登录成功 | 上传、编辑题面、讲解、保存 | 退出登录 / 进入 admin |
| `confirm` | 初始/重新开始 | 上传、编辑题面 | 点击确认进入 `hint` |
| `hint` | 确认题面或普通追问 | 获取提示、语音/文字追问 | 点击完整解析进入 `explain` |
| `explain` | 请求完整解析 | 继续追问、保存记录 | 重新开始 |
| `admin` | 管理员侧栏 | 查看统计、改用户角色/状态 | 返回课堂 |

前端：

- `localStorage.math_coach_token` 保存登录 token
- `localStorage.mathCoachSaved` / `mathCoachProgress` 保存学习记录与进度
- API 统一附加 `Authorization`；收到 401 时清理 token 并回到登录页

## 10. 错误与安全处理

- 非 PNG/JPEG/WebP 或超过 8 MB 的文件走 Mock/可读回退，不进入真实模型请求。
- Pydantic 对题面、消息、音频 Base64 长度和采样率做边界校验。
- 模型异常不返回 Python 堆栈；真实错误仅记录在服务端日志上下文中。
- CORS 默认只开放本地开发来源，生产部署应通过环境变量显式设置。
- 密码哈希不可回读；`public_user` 不返回 `password_hash`。
- `/api/session/{session_id}` 仅删除服务端课堂会话，不影响登录会话和本地记录。


## 前端实现（React）

- 目录：`frontend/`（Vite + React 19 + TypeScript）
- 入口：`frontend/index.tsx` / `frontend/App.tsx`
- 服务层：`frontend/services/{api,authService,adminService,lessonService}.ts`
- 登录门禁：无 token 时渲染 `AuthModal`；401 清理 token 并回到登录
- 视图：`workspace` / `history` / `admin`
- SSE：`POST /api/lesson/stream` 解析 `session` / `text_delta` / `lesson` / `done`
- 构建：`npm run build` → `frontend/dist`，由 `app.py` 托管；无 dist 时回退 `static/`
